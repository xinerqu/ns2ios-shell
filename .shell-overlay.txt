# What this fork changes on top of seedds/nxnative, in the form CI applies it.
#
#   + path   a file this fork adds: copied onto the upstream tree as it is
#   ~ path   a file this fork modifies: the matching .shell-patches/*.patch is applied to the upstream file
#   - path   a file upstream has and this fork does not carry: CI must not copy it, and it must be gone here too
#   ! path   outside what this fork maintains: the assembler does not use it, and a difference there is not drift
#            (this fork's own docs and tools, upstream's Mac front end and dev scripts, the screenshots, upstream's CI)
#
# `scripts/check_tree.py` judges the whole tree against these lines and fails on anything undeclared: a change this fork
# carries in a file no line names never reaches the shell, and nothing else would notice. CI runs it in Report drift.
#
# The patches are unified diffs against the base commit recorded in .shell-base.txt, so an upstream change elsewhere in one of
# these files merges automatically instead of being lost by a whole-file copy. Only a change to the same lines makes `git apply`
# fail, and that is the one case that needs a human. A patch left over from an older base keeps applying for the same reason.
#
# When you add or modify a file for the shell route, add it here -- and for a "~" entry, regenerate its patch with
# `python dm/ios/tools/make_shell_patch.py <path>` (or --all), which diffs this tree against the base commit and handles CRLF.
